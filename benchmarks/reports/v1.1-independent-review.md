# v1.1 Independent Review and Hardening Report

Date: 2026-09-24  
Scope: source, tests, packaging, CI, sample data, API/UI, and benchmark provenance

## Findings that changed the project

### Critical — BM25 direction

The v1.0 query computed `-bm25(fts)` and then sorted ascending, retaining the weakest matches. Existing tests mostly used single-hit queries and did not expose it.

**Fix:** strongest-first `ORDER BY score DESC, doc_id ASC` plus a deterministic multi-hit regression test.

### Critical — rerank metric identity

Reranking reordered hits by cosine but left the old fusion score on each `Hit`. ranx sorts runs by score, so evaluation could undo the cosine order.

**Fix:** rerank now creates new hits with cosine scores, retrieves a configurable 50 candidates per leg by default, preserves the complete fused union, and encodes the query once.

### High — native float retrieval

Production semantic float search previously loaded the full vector corpus into NumPy.

**Fix:** float mode now executes sqlite-vec cosine KNN. Int8/binary remain exact application-side scans, but use bounded 2,048-row blocks.

### High — evaluation safety

The original harness could add a partial run to an arbitrary existing index.

**Fix:** evaluation builds in a unique staging database, validates output, writes a dataset/configuration/model manifest, and atomically publishes only on success. Alpha sweeps verify the manifest before loading the model.

### High — UI content safety

The prototype inserted raw FTS snippets with `innerHTML`.

**Fix:** snippets are converted to validated text/highlight segments, all dynamic content is rendered with DOM text nodes, assets are same-origin package files, and CSP/defensive headers are enabled.

### High — identity and vector consistency

Stem-only IDs could collide. Lexical updates could leave stale vectors, and a failed embedding batch could leave a partial transaction.

**Fix:** schema v2 uses canonical relative filenames, embedded indexes reject lexical-only writes, model attachment backfills missing vectors, encoder output is validated, batches roll back, and health checks detect missing/orphan vectors.

### High — clean installation

The v1.0 CI used uppercase `OneFind` on Ubuntu while the installed script was lowercase and did not declare NumPy for the dev test profile.

**Fix:** canonical lowercase CLI, explicit bounded dependencies, mandatory core CI, full-stack CI, and wheel-content verification.

## Retrieval and UI additions

- 20-document cross-domain offline corpus.
- 26 gold lexical/semantic/hybrid/no-answer queries.
- `onefind smoke` quality command.
- Packaged responsive, accessible, dark-mode UI.
- Capability-aware search modes and precision controls.
- Explicit request cancellation and stale-response protection.
- Bounded quantized scan with external cache invalidation.
- MIT license and version 1.1 package metadata.

## Verification

- 112 automated tests.
- Mandatory model-free regression profile.
- Local MiniLM integration profile.
- JavaScript syntax validation.
- Wheel build and isolated non-editable import.
- Packaged HTML/CSS/JavaScript presence check.
- Historical affected benchmark reports explicitly marked superseded.
- 21 real-browser screenshots covering all documented UI states and retrieval combinations, with a machine-readable assertion manifest.

## Honest conclusion

The v1.0 reports were useful for exposing the architecture but were not reliable evidence after the BM25 and rerank defects were found. v1.1 prioritizes correctness and reproducibility over preserving attractive historical numbers.
